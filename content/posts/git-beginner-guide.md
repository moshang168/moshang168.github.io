## 为什么一定要学Git

以前改代码或者写文档，大家都是这么备份的：`最终版.docx`、`最终版真的不改了.docx`、`最终版打死不改了.docx`，改坏了找不回历史版本，多人协作的时候互相覆盖文件。Git就是解决这个问题的版本控制工具，记录你文件的每一次修改，随时可以回滚到任何一个历史版本，多人协作的时候自动合并代码，是现在所有程序员和写作者的必备工具。

---

## 核心概念先搞懂

新手学Git先记三个最核心的概念，剩下的命令都是围绕这三个概念来的：
1. **仓库（Repository）**：就是你项目的文件夹，Git会在里面记录所有文件的修改历史
2. **提交（Commit）**：就是给你的项目拍一个快照，写清楚这次改了什么，之后随时可以回到这个快照
3. **分支（Branch）**：相当于开了一个平行副本，你可以在分支上随便改代码，改完没问题再合并回主分支，不影响主线版本

---

## 第一步：安装与基础配置

安装好Git之后，打开终端先配置你的身份，这样每次提交的时候Git知道是谁改的代码：
```bash
git config --global user.name "你的昵称"
git config --global user.email "你的邮箱"
```

## 日常最常用的命令（90%场景只用这几个）

| 命令 | 作用 |
|------|------|
| `git init` | 在当前文件夹初始化一个Git仓库 |
| `git clone 仓库地址` | 把远程仓库的代码下载到本地 |
| `git status` | 查看当前文件夹哪些文件被修改了 |
| `git add 文件名` | 把修改的文件加入待提交列表 |
| `git commit -m "本次修改说明"` | 把待提交的修改打包成一个快照 |
| `git push` | 把本地提交的内容推送到远程仓库 |
| `git pull` | 把远程仓库的最新修改拉到本地 |
| `git log` | 查看所有历史提交记录 |

## 新手最容易用到的救命操作

### 1. 改坏了想撤回上次的提交
如果你改完代码发现改错了，想回到上次提交的状态：
```bash
git checkout .
```
所有修改过的文件都会恢复到上次提交时的样子。

### 2. 提交错了想撤销
如果你刚commit完发现提交错了，想退回上次的状态重新提交：
```bash
git reset --soft HEAD^
```
修改的内容还会保留在你的文件夹里，只是撤回了刚才的提交。

### 3. 看某个文件之前的版本
打开git log找到对应的提交ID，然后执行：
```bash
git show 提交ID:文件名
```
就能看到这个文件在那个历史版本里的内容。

## 分支操作基础

多人协作或者开发新功能的时候不要直接在主分支上改，新建一个分支：
```bash
# 新建并切换到新分支
git checkout -b 新功能名

# 改完代码提交之后，切回主分支
git checkout main

# 把新分支的内容合并回主分支
git merge 新功能名
```

就这么几个命令，就能覆盖日常90%的使用场景，不用一开始就去学复杂的rebase、变基之类的高级操作，日常开发这几个命令就完全够用了。
